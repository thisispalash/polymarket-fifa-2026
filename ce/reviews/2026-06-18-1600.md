## Verdict — **Not ready to deploy with real money**

Three blockers make the production build unsafe regardless of how cleanly it typechecks:

1. **The PWA is dead behind the `/api` prefix.** Web calls `/api/*`, server mounts at root, and `setNotFoundHandler` explicitly skips `/api` for the SPA fallback. User cannot unlock.
2. **MARKET BUY orders bypass the capital cap entirely.** `cost = size * (price ?? 0) = 0` for MARKET, so the cap check is a no-op for the most common mobile action.
3. **Arb execution is one-sided on first failure.** Legs fire sequentially and abort on first reject; placed legs are never unwound, so the user ends up net-directional — the exact opposite of arbitrage.

Everything else can ship as a follow-up wave.

## Suggested fix order before any real-money deploy

1. **#1 — `/api` prefix.** ✅ Fixed in commit (see git log). Took the inverse direction from the original suggestion: web kept its `/api/...` literals (which were already there), server wraps all route plugins in a single `app.register(api => {…}, {prefix:"/api"})` block including `/healthz`, Vite proxy drops the rewrite, `railway.json` healthcheck moves to `/api/healthz`. Session-gate allowlist updated to `/api/healthz`, `/api/unlock`, `/api/session`.
2. **#2 — MARKET cost.** ✅ Fixed. Extracted `computeOrderCostUsdc(input)` to `caps.ts` with branch: MARKET BUY → `input.size` (USDC amount), LIMIT (either side) → `input.size × input.price`, MARKET SELL → 0 (sell recoups capital, doesn't deploy it — left out of the cap by design). 5 new tests in `caps.test.ts` lock the formula.
3. **#3 — Naked legs.** ✅ Fixed. New `server/src/safety/unwind.ts` exports `cancelLegsBestEffort(orderIds, ctx)` which `Promise.allSettled`s a `cancelOrder` per leg and reports back `{cancelled, failedIds}`. Both `arbs.ts` (manual `/arb/execute`) and `arbScan.ts` (auto-exec) track `placedOrderIds` as they go and call the helper on any leg failure. Failed cancels are surfaced in the 409 response body (`unwindFailures: [...]`) and logged loud. 4 new tests in `unwind.test.ts` cover empty/all-success/partial-failure/all-failure paths.
4. **#4 — Kill switch escape.** `setKillSwitch(true)` in `system.ts` should also `stopWorkers()` BEFORE `cancelAll()`. In `submitOrder.ts`, re-check `isKillSwitchEnabled()` after the SDK call returns; if the switch was tripped during the call, `cancelOrder` the just-placed `response.orderId`.
5. **#5 — `edgePct` units.** Pick one place to do the `×100`. Either `dutchArb.ts:21` returns the fraction (`1 - sumPrice`) and `arbs.tsx` keeps its `×100`, or `dutchArb` keeps the percent and `arbs.tsx` drops the second `×100`. Adjust the `arbOpportunities.edgePct` column's stored meaning and any tests.
6. **#6 — Clearable kill switch.** Extend the POST body to `{enabled: boolean, reason?: string}`, branch on `enabled`. Settings UI then gets a "Deactivate" button alongside the existing "Activate."
7. **#7 — Manual arb path uses strategy cap.** Thread the `dutch_arb`/`yesno_arb` strategy id into the `submitOrder` call in `routes/arbs.ts:92`. (Look it up from `strategyConfigs` by `kind` once at the top of the handler.)
8. **#13 — Replace cookie-equals-SECRET with a server-side session id.** Generate a random opaque token on `/unlock`, persist `{token_hash, created_at}`, send the token as the cookie, validate via DB. Now leaks are revocable and the env secret never leaves the server.
9. **#14 — Wire SIGTERM.** `process.on("SIGTERM", async () => { stopWorkers(); await app.close(); process.exit(0); })`. Same for SIGINT.

After those nine, the remaining P1 set (#8–#12, #15–#25) can ship as a second wave with a separate review. The P2/P3 list is housekeeping that can ride alongside feature work.
